# 1.10.7

## 原因与修复

已从安装版 OCR 子进程捕获原始字节：中文识别结果以 GBK 输出，而主进程 readline 使用 UTF-8 解码，产生“�”等替代字符。原始结果按正确编码读取后中文正常。

- Python 进程显式设置 UTF-8 输入 / 输出，并使用 ASCII 安全的 JSON Unicode 转义。
- 按完整字节帧读取后再解码，避免拆分多字节字符。
- 兼容旧版 GBK / CP936 输出，保留其编码状态；新协议明确重置为 UTF-8。
- 中文文字、表格、翻译位置及错误提示均使用同一协议，非法结果明确报错，不输出损坏文本。
- 私人包内 OCR 可执行程序已重新构建，模型与现有识别功能继续内置，无需用户重新配置。

## 验证

213 项功能测试通过。真实模型验证中文两行正文、中文表格、TSV 与 Excel 工作表中文、图片翻译文字坐标和 LaTeX 公式；4 个识别响应都只有 ASCII 协议字节。兼容读取旧安装版的 GBK 输出也通过。验证未打开测试页面，未改动用户剪贴板。

旧版已生成的乱码丢失了原始字符，需从原图重新提取一次；新识别结果会正常显示。
